# aTworks AI MVP — 채팅 기능 정리

작성일: 2026-11-03 · 대상 브랜치: `feature/self-growth` (작업 트리, 미커밋 변경 포함)

어시스턴트 패널 하나로 aTworks의 API·실행 이력·실행 계획(job)·검증 규칙을 묻고 다루는 채팅이다.
각 기능을 어떤 질의로 확인하는지는 [chat-test-queries.md](chat-test-queries.md)에 정리했다.

## 1. 구조와 원칙

| 층 | 역할 | 위치 |
|---|---|---|
| 포털(웹) | 화면, 어시스턴트 패널, 카드 렌더링 | `web/atworks-web`, 공용 부품 `web/web-shared` |
| host(서버) | 세션·대화 저장, 채팅 스트리밍(SSE), 승인 라우트, 스케줄러 | `host/atworks_host` |
| 에이전트 | 모델 호출 루프, 도구, 가드레일, 프롬프트, 스킬 | `atworks-agent/` |
| 모델 | Anthropic Messages 형식. 개발은 OpenRouter, 폐쇄망은 LiteLLM (지금은 Qwen) | `.env`의 `ANTHROPIC_BASE_URL` |

**원칙: 모델은 초안만 쓰고, 판정·실행·승인은 코드와 사람이 한다.**
- 성공·실패 판정은 aTworks 규칙(백엔드)만 만든다.
- 실행은 스테이징 → 사람의 승인 클릭 → 스케줄러 순서로만 일어난다.
- 승인은 카드나 Jobs·Rules 화면의 버튼으로만 된다. 채팅으로 "승인해"라고 해도 아무것도 승인되지 않는다.

## 2. 무엇을 물어볼 수 있나 (업무 흐름)

| 흐름 | 하는 일 | 대표 카드 |
|---|---|---|
| 실패 분석 | 실패·에러 run 조회 → 위험도 순위(`risk_v1`) → 먼저 볼 항목 | 실행 요약 `run_digest` |
| 원인별 묶기·언제부터 | 실패 원인·API·환경 등으로 묶기, 첫 실패 시각, 불안정(flaky) 판정 | `run_groups` |
| 자유 집계 | 기간·필터·축을 조합한 집계 표 | `query_table` |
| 실행 계획 | API 선택 → 환경·스케줄·테스트 데이터 → job 스테이징 → 승인 | `job_preview`, 질문 폼 |
| 승인 관리 | 승인 대기 목록, 이미 처리된 항목 안내, 취소 | `job_preview` |
| API 조회 | 명세, 파라미터, 규칙 확인 | 텍스트, 화면 이동 |
| 검증 규칙 | 자연어 → 규칙 초안(수치·코드값·필수·포맷) → 영향 미리보기 → 승인 | `rule_preview`, `format_batch` |
| 값 병행 비교 | 두 서버(legacy·renewed) 응답 비교 → 노이즈 무시 프로파일 | `parity_summary`, `profile_preview` |

## 3. 화면과 대화의 연동

- **화면 → 채팅(첨부)**: 목록 행의 "채팅에 첨부"로 API·run·job을 질문에 붙인다. 첨부하면 입력창에 바로 커서가 간다. 첨부된 항목이 그 턴의 범위가 된다.
- **채팅 → 화면(지시)**: 모델이 뷰 이동, 필터, 항목 강조(①②③ 박스)를 한다. 화면만 바꾸며 아무것도 실행하지 않는다.
- **화면 상태 전달**: 매 질문에 지금 보는 뷰, 필터, 보이는 항목과 **각 행의 상태**(승인됨·대기·실패 등)가 함께 간다. 모델은 화면 내용부터 반영해 답한다.

## 4. 상태를 "지금" 기준으로 말하기

- 매 턴 시작 때 백엔드에서 **승인 대기 목록**(job·규칙·비교 프로파일·포맷 묶음)과 **이 대화가 다룬 항목의 현재 상태**를 다시 읽어 모델에게 준다(`state_now`). 대화가 기억하던 옛 상태도 이 값으로 바뀌어, 카드도 현재 상태로 그려진다.
- "승인이 필요하다·대기 중이다·실행됐다"는 말은 이 현재 상태나 이번 턴의 도구 결과로만 한다. 승인 요청은 실제 대기 목록에 있는 항목에만 한다.
- 이미 승인·취소된 항목에 모델이 적용·취소를 시도하면, "이미 적용됨(누가, 언제)"이라는 사실을 돌려받는다. 예전처럼 "승인 대기 중"이라는 잘못된 안내가 나오지 않는다.

## 5. 대화 관리

| 기능 | 동작 |
|---|---|
| 대화 저장 | 세션 하나가 대화 하나다. 상태·모델용 원본·화면 기록(답변·카드·chip)을 SQLite에 저장해 host를 재시작해도 남는다. |
| 새 대화 | 패널 헤더의 말풍선+ 버튼. 이전 대화는 그대로 남는다. 지금 대화가 비어 있으면 비활성. |
| 대화 기록 | 시계 버튼. 제목 검색, 열기, 이름 바꾸기, 삭제(두 번 눌러 확인). 진행 중인 대화는 "답변 중·대기 N·백그라운드 답변 중"으로 표시되고 삭제가 막힌다. |
| 다시 열기 | 화면 기록과 모델 맥락이 함께 복원돼 그대로 이어서 묻는다. 승인 카드는 열 때 현재 상태를 다시 읽는다. |
| 새로고침 복원 | 마지막 대화(답변을 시작한 대화 포함)가 다시 열린다. |
| 대기열 | 답변 중에 보낸 메시지는 입력창 위에 쌓였다가 순서대로 자동 전송된다. 끌어서 순서 변경, 편집(입력창으로 되돌림), 삭제. 보낼 때의 첨부를 함께 묶고, 화면 상태는 실제 전송 시점 것을 쓴다. 새로고침해도 남는다. |
| 백그라운드 | 답변 중이거나 대기열이 남은 채 다른 대화로 옮겨도, 원래 대화는 끝까지 처리·저장된다. 돌아오면 결과가 보인다. |
| 연결 끊김 이어받기 | 턴은 연결과 분리되어 서버에서 끝까지 돈다. 끊기면 "연결이 끊겨 다시 연결하는 중…" 후 진행 중 답변을 처음부터 다시 받아 채운다. 새로고침해도 진행 중 턴을 이어 받는다. |
| 입력 초안 저장 | 쓰다 만 글과 올려 둔 첨부가 대화별로 저장돼 새로고침·대화 전환 후에도 남는다. |

## 6. 입력과 읽기 편의

- **질문 폼**: 모델이 빠진 정보를 미리 채운 폼으로 묻는다(최대 5문항).
  - 시간: 24시간제. 자주 쓰는 시간 버튼과, 새벽·오전·오후·저녁 6시간 단위 격자 + 분 버튼.
  - 숫자: 큰 −/+ 버튼, 직접 입력, 기간이면 1·3·5·7·14일 빠른 선택.
  - 날짜: 오늘·내일·다음 주 월요일 빠른 선택 + 달력.
  - 대상 환경·서버: 항상 여러 개 선택 가능.
- **추천 chip**: 매 답변 끝에 다음 행동 최대 4개. 답변이 질문으로 끝나면 그 답이 chip이 되고, 빠지면 "네/아니요"가 붙는다. 승인·취소용 chip은 만들지 않는다. 칩은 그것만 보고 무슨 항목인지 알 수 있어야 해서, 번호만 다른 같은 문구("① 실행 상세 보기" 반복)는 서버가 거절하고 항목 이름을 넣게 한다. 답변 글도 카드도 없이 칩만 보내는 답도 서버가 거절해 먼저 글로 답하게 한다.
- **인용해서 묻기**: 답변 글을 드래그하면 "인용해서 묻기" 버튼이 뜨고, 입력창 위에 "인용 N개" 칩이 붙는다. 보낼 때 인용문이 질문 앞에 붙는다.
- **질문 내비게이션 레일**: 질문이 3개 이상이고 대화가 화면을 넘으면 오른쪽에 질문 위치 마커가 생긴다. 올리면 질문 내용, 누르면 그 질문으로 이동.
- **질문 복사**: 내 질문 말풍선에 마우스를 올리면 복사 버튼.
- **job 카드 대상 API**: 생략 없이 한 줄에 하나씩, method 색 포함(10개 초과 시 카드 안 스크롤).

## 7. 진행과 오류 표시

- **진행 중 표시**: 회전 표시 + 현재 단계 문구(빛 효과) + 점 세 개 + 3초 이후 경과 초.
- **단계 표시**: 여러 단계 작업이면 입력창 위에 "2/4단계 · 현재 단계"를 고정한다. 단계는 실제 도구 결과가 도착해야 완료로 표시된다. 모델이 단계 목록을 주지 않으면 "N단계 진행 중 · 현재 작업"으로 진행만 보여준다.
- **글자 흐름 효과**: 스트리밍 글이 덩어리가 아니라 자연스럽게 흘러나온다(동작 줄이기 설정 시 즉시 표시).
- **오류 카드**: "답변을 끝까지 만들지 못했습니다" + 원인 문구 + 다시 시도·오류 진단 복사·로그 내보내기. 다시 시도는 마지막 답변에만 있다.
- **누설 표시 정리**: 모델이 도구 호출 표기(`<tool_call>` 등)를 글로 흘리면 화면에서 걸러낸다.

## 8. 가드레일 (요약)

자세한 기준은 [safety.md](safety.md).
- **코드로 강제**: 판정 불변, 출처 검증(세션에서 본 ID만), 실행 규모 상한(job 생성·승인·실행 때 세 번 검사), 허용 환경(dev·stg·legacy·renewed, prod 차단), 사람 승인 필수, 감사 로그, 스케줄 실행에 모델 없음, 첨부 격리, 고정 도구 목록, 개인정보 마스킹.
- **모델 지시**: 숫자·상태는 도구 결과로만, 첨부가 턴의 범위, 지어낸 테스트 데이터는 가정으로 표시, 범위 밖 질문(예: 날씨)은 `note_unmet_ask`로 기록 후 무엇이 있으면 답할 수 있는지 안내.
- **배포 시 채울 것**: 인증, 승인 권한(누가 누를 수 있나), 호출 제한, 상한값 조정, 로그 관리.

## 9. 저장 위치와 설정

| 항목 | 위치·설정 |
|---|---|
| 대화 저장 | `ATWORKS_CONVERSATIONS_PATH` (기본 `host/atworks_host/conversations.sqlite`) |
| 실행 데이터 | `ATWORKS_STORE_PATH` (기본 메모리), `ATWORKS_FIXTURES_DIR` (데모 픽스처 또는 합성 데이터셋) |
| 브라우저 저장 | 마지막 대화, 대기열, 입력 초안(글·첨부), 패널 폭 — `localStorage` |
| 모델 | `ANTHROPIC_BASE_URL`, `ANTHROPIC_AUTH_TOKEN`, `ATWORKS_MODEL` |

## 10. 알려진 한계

- **긴 대화 요약 없음**: 10만 토큰을 넘으면 오래된 도구 결과만 지운다. 이전 대화 요약은 미구현.
- **답변 중지 버튼 없음**, **대화 분기(여기서부터 새 대화) 없음**.
- **job·규칙 원장은 메모리**: host를 재시작하면 데모 job·규칙이 사라진다(대화 기록은 남는다).
- **단계 도구 호출은 모델 의존**: Qwen은 `present_plan`을 잘 부르지 않아, 대개 "N단계 진행 중" 대체 표시가 나온다.
- **인증 없음**: 운영자는 화면에서 고른 값을 그대로 믿는다.
- **날짜 의존 테스트 13건 실패**: 고정 날짜(2026-09) 픽스처가 30일 창을 벗어나 생기는 것으로, 이번 변경과 무관하다.
